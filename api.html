API del Tanaj

JSON de solo lectura, sin claves, sin backend: cada archivo del repositorio es un endpoint. 39 libros · 929 capítulos · 23.213 versículos en hebreo y 23.129 en español.

Endpoints

RutaQué devuelve
/v1/index.jsonSecciones, orden judío, libros (con alias), conteos y fuentes.
/v1/he/<libro>/<capítulo>.jsonCapítulo en hebreo (WLC) con niqqud, te'amim y he_plain sin marcas.
/v1/es/<libro>/<capítulo>.jsonCapítulo en español (RV1909) + bloque alignment.
/v1/search/<torah|neviim|ketuvim>.jsonÍndice de búsqueda: [referencia, hebreo sin niqqud, español normalizado].
/v1/align.jsonDiferencias de numeración hebrea ↔ española (142 capítulos) y libros con regla curada.
/v1/manifest.jsonRuta, bytes y sha256 de cada archivo (integridad).
/v1/books/<libro>.jsonLibro completo he+es (opcional: --books en el build).

Ejemplos

# capítulo completo (hebreo)
curl -s https://avisonofgod.github.io/v1/he/bereshit/1.json | head -c 400

# Shemá, verso 4 de Devarim 6
curl -s https://avisonofgod.github.io/v1/he/devarim/6.json | jq '.verses[3]'

# español del mismo capítulo
curl -s https://avisonofgod.github.io/v1/es/devarim/6.json | jq -r '.verses[3].es'

# alias: "genesis" es lo mismo que "bereshit"
curl -s -o /dev/null -w "%{http_code}\n" https://avisonofgod.github.io/v1/he/genesis/1.json   # 404: usa slugs canónicos

Los alias (genesis, exodo, salmos…) se resuelven en el lector; en la API la ruta canónica es el slug hebreo (bereshit, shemot, tehilim…).

Formato de un versículo

{
  "ref": "בְּרֵאשִׁית 1",          // hebreo (o "Génesis 1" en /es/)
  "ref_en": "Genesis 1",
  "book": { "slug": "bereshit", "he": "בְּרֵאשִׁית", "es": "Génesis",
            "en": "Genesis", "section": "torah", "order": 1 },
  "chapter": 1,
  "lang": "he",
  "source": "Westminster Leningrad Codex (morphhb, CC BY 4.0)",
  "verses": [
    { "n": 1,
      "he": "בְּרֵאשִׁ֖ית בָּרָ֣א אֱלֹהִ֑ים אֵ֥ת הַשָּׁמַ֖יִם וְאֵ֥ת הָאָֽרֶץ׃",
      "he_plain": "בראשית ברא אלהים את השמים ואת הארץ" },
    { "n": 5, "he": "…", "he_plain": "…", "marker": "פ" }
  ],
  "counts": { "verses": 31 }
}
  • he: texto del códice con niqqud y te'amim, en NFC.
  • he_plain: el mismo texto sin signos (búsqueda, comparación, transliteración).
  • marker: marca de párrafo del códice: פ (petuĥá) o ס (setumá).
  • En español, alignment indica he, es, diff y si la numeración coincide; es_ref aparece cuando la cita de la RV1909 es distinta (Yoel, Malaquías).

Numeración hebrea vs. española

El Tanaj y la RV1909 no parten igual todos los versículos. La API nunca mezcla: el hebreo conserva la numeración masorética (23.213 versículos) y el español la suya (23.129). /v1/align.json documenta los 142 capítulos donde difieren:

  • versiculo_desplazado (135): el capítulo tiene distinto número de versículos (p. ej. בְּמִדְבַּר 16: hebreo 35 / español 50).
  • capitulos_distintos (7 en יוֹאֵל y מַלְאָכִי): el libro se parte en otros capítulos; el español se reubica y cada versículo trae es_ref con su cita original.

CORS, caché y uso desde otra web

GitHub Pages sirve JSON estático; si necesitas CORS explícito o caché inmutable por versión, usa el mismo repositorio vía jsDelivr (añade Access-Control-Allow-Origin: * y Cache-Control largo):

https://cdn.jsdelivr.net/gh/avisonofgod/avisonofgod.github.io@main/v1/he/bereshit/1.json

Los archivos no cambian entre builds (si cambian, cambia el sha256 del manifiesto), así que se pueden cachear agresivamente. Para publicar una versión congelada, fija un tag: @v1.0.0.
